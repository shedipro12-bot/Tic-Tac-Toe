# תוכנית אבן דרך 1 — בחירת קושי והשלמת משחק

סטטוס: אבן הדרך הראשונה מומשה ונבדקה; ממתינה לבדיקה ולאישור המפתח. תוצאות וראיות ב־[דוח המסירה](MILESTONE-1-REVIEW.md).

## מטרה ובסיס התכנון

לספק אפליקציית נייד ניתנת להרצה שבה המשתמש בוחר Easy, Medium או Hard, מתחיל משחק כ־X מול מחשב O, ומשלים משחק תקין עד ניצחון, הפסד או תיקו.

התוכנית מבוססת על [Codex.md](../Codex.md), [אבן הדרך הראשונה](MILESTONES,md.md), [PRD](PRD.md.md), [ARCHITECTURE](ARCHITECTURE.md.md), [DESIGN](DESIGN.md.md), [Wireframes](wireframes.png.png), [Mockups](mockups.png.png) ו־[Style guide](style-guide.png.png). תנאי הסיום המקוריים מחייבים גם אם פירוט בתוכנית זו אינו חוזר על כולם.

מצב ההתחלה: קיימים מסמכי אפיון ותמונות ייחוס; אין אפליקציה, package.json או תשתית בדיקות. התוכנית אינה מניחה שיש יכולת קיימת או אבן דרך שאושרה.

## היקף ותוצר למשתמש

- מסך פתיחה באנגלית: כותרת, “Play against the computer.”, בורר קושי ו־Start Game. Medium נבחר כברירת מחדל.
- מסך משחק: לוח 3×3 ריק בתחילה, רמת הקושי הפעילה, “You: X”, “Computer: O” והודעות “Your turn” / “Computer’s turn”.
- תוצאה באותו מסך: “You win”, “Computer wins” או “Draw”; הלוח נעול, וקו ניצחון סטטי בניצחון של אחד הצדדים.
- שגיאה פנימית: הודעה קצרה באותו מסך וכפתור Restart להתאוששות, ללא חלון אישור וללא מסך שגיאה נוסף.
- מראה דשא/עץ/גיר, Nunito Sans מקומי, נגישות ופריסה המתאימה לנייד לאורך ולרוחב.

היקף זה אינו כולל מונים, Restart רגיל במהלך משחק, Play Again, שינוי קושי לאחר תוצאה, Settings, אודיו, אנימציות משוב, PWA/Service Worker, offline, התקנה או פרסום. אין להציג עבורם כפתורי דמה. לאחר תוצאה המשחק נשאר נעול; לצורך משחק נוסף בגרסה זו ניתן לרענן ולחזור לפתיחה. Restart מופיע רק לצורך התאוששות משגיאה.

## סדר העבודה

### 1. הקמת אפליקציה ניתנת להרצה

- לבדוק סביבת Node/npm ולבחור גרסאות יציבות ותואמות של React, TypeScript ו־Vite בעת המימוש; לתעד דרישות Node ולשמור package-lock.json.
- להקים Vite עם React ו־TypeScript strict, CSS Modules ו־StrictMode בפיתוח, בלי לפגוע בקבצי spec.
- להגדיר סקריפטים להרצת פיתוח, בדיקת טיפוסים, Vitest, בניית production, preview ובדיקות Playwright. שמות מתוכננים: `dev`, `typecheck`, `test`, `build`, `preview`, `test:e2e`.
- ליצור רק את התיקיות והרכיבים הדרושים לפרוסה זו. אין צורך בהתקנת PWA, שירות אודיו או ספריית state נוספת.

תוצר: מסך פתיחה בסיסי שניתן להריץ ולבנות, ותשתית בדיקות עובדת.

### 2. חוקי משחק ומכונת מצבים

- להגדיר Board בלתי משתנה בן תשעה תאים, Mark, Difficulty, Phase, Outcome ו־WinningLine בהתאם לחוזי הארכיטקטורה.
- לממש `getLegalMoves`, `applyMove`, `evaluateBoard` וכל שמונת קווי הניצחון; לבדוק ניצחון לפני תיקו.
- להקים reducer טהור עם מצבי `setup`, `human-turn`, `computer-turn`, `finished`, `error`; לשמור לוח, קושי נבחר/פעיל, תוצאה, קו ניצחון, `matchId`, `ply` ושגיאה בזיכרון בלבד.
- לממש פעולות בחירת קושי בפתיחה, התחלת משחק, מהלך אדם, מהלך מחשב, שגיאה והתאוששות. מונים והעדפות יתווספו כשיגיע שלבם, ללא תשתית תפקודית מוקדמת עבורם.
- לתפוס קושי בתחילת המשחק, להתחיל תמיד ב־X ולחסום שינוי קושי במהלך משחק ובתוצאה בגרסה זו.
- לבדוק אינדקס שלם בטווח, תא פנוי ותור תקין. מהלך מחשב חייב להתאים גם ל־`matchId` ול־`expectedPly`; פעולות כפולות או ישנות אינן משנות מצב.
- בעת התאוששות: להגדיל `matchId`, לאפס לוח/תוצאה/שגיאה/ply ולהתחיל בתור האדם באותה רמת קושי. לא לחשוף התאוששות כפעולת משחק רגילה.

תוצר: מנוע משחק שניתן לבדיקה ללא React או דפדפן, כולל סיום ונעילה אמינים.

### 3. יריב מקומי בשלוש רמות

- לממש Minimax מנקודת מבט O: ניצחון `+1`, תיקו `0`, הפסד `-1`; עומק מכריע שוויון בתוך אותה קטגוריית תוצאה בלבד.
- לחלק מהלכים חוקיים לבעלי התוצאה הטובה ביותר ולבעלי תוצאה גרועה ממנה. ענף טעות בוחר מהקבוצה הגרועה כשהיא קיימת; אחרת מהקבוצה הטובה.
- לרכז הסתברויות טעות בקובץ תצורה: Easy `0.50`, Medium `0.25`, Hard `0.10`. אלו הסתברויות ענף ולא שיעורי ניצחון מובטחים.
- לאפשר RNG מוזרק לבדיקות ו־Math.random בהרצה רגילה. לא להוסיף כלל ניצחון/חסימה קשיח שמבטל את האפשרות לטעות ב־Hard.
- לבדוק קלט תקין של תור מחשב ולוח שאינו סופי; תמיד להחזיר תא פנוי. אין רשת, מודל AI או Web Worker.

תוצר: כל רמה בוחרת מהלכים אסטרטגיים וגם יכולה לטעות, עם מסלול מוכח לניצחון אנושי מול Hard.

### 4. חיבור המשחק ותזמון תור המחשב

- לחבר reducer ל־React באמצעות `useGameController`; רכיבי התצוגה שולחים פעולות ואינם משנים לוח ישירות.
- בתור מחשב לתזמן timer יחיד של `400 ms` עם צילום לוח בלתי משתנה, קושי, `matchId` ו־`ply`. לנקות אותו בשינוי dependencies וב־unmount.
- לוודא שהבדיקות ב־reducer מונעות מהלך כפול גם בהרצה חוזרת של effects ב־StrictMode.
- בביטול נראות לנקות timer; בחזרה לדף לתזמן השהיה חדשה אם עדיין תור מחשב. סיום, שגיאה והתאוששות מבטלים עבודה ישנה.
- ללכוד שגיאת יריב ולשלוח שגיאה רק לדור המשחק הרלוונטי; אין דיווח מרוחק או הצגת stack trace למשתמש.
- ליישם AppErrorBoundary להתאוששות משגיאת render באמצעות הפעלה חדשה. להבחין בין התאוששות זו לבין Restart של שגיאת משחק השומר על הקושי הפעיל.

תוצר: מסלול מלא מבחירת קושי דרך חילופי תורות ועד תוצאה, עם התאוששות שאינה מקבלת callbacks ישנים.

### 5. עיצוב ונגישות של המצבים הכלולים

- לבנות SetupPanel, DifficultySelector, GameScreen, Board ו־CellButton; להשתמש באותו GameScreen לכל התורות והתוצאות.
- ליישם tokens מתוך DESIGN: ירוק לוח, צהוב X, סגול O, קרם, מסגרת עץ ורקע דשא, טיפוגרפיה וריווח מוגדרים.
- לארוז Nunito Sans ונכסי רקע/מרקם מקומית, עם רישוי מתאים. התמונות ב־spec הן גיליונות ייחוס, לא נכסים נפרדים מוכנים לשימוש; להכין נכסים מתאימים בלי להציג צילום של ממשק במקום רכיבים פעילים.
- להשתמש בלוח CSS Grid עם כפתורים טבעיים ותוויות שורה/עמודה/תכולה, בורר קושי עם מצב נבחר נגיש, focus ברור ו־live region לתור ולתוצאה.
- להקפיד על יעדי מגע לפחות 44×44px, כפתור ראשי בגובה התחלתי 48px, ניגודיות טקסט AA וסימנים וקו ניצחון הניתנים להבנה ללא צבע.
- לבדוק portrait ו־landscape, safe-area וגלילה אנכית במסך נמוך; אין חיתוך כפתורים, overflow אופקי או חסימת zoom.
- לשמור על משוב סטטי באבן דרך זו. הודעות וקו ניצחון אינם תלויים באודיו או בתנועה.

תוצר: מסכי פתיחה, תורות, תוצאות ושגיאה קריאים וניתנים להפעלה במגע ובמקלדת.

### 6. אימות והכנת מסירה

הבדיקות ייכתבו לצד המימוש הרלוונטי; שלב זה משלים בדיקות משולבות ואוסף ראיות:

- להריץ בדיקת טיפוסים, Vitest, build ו־Playwright מול preview של גרסת production; לתעד סביבה ופקודות בפועל.
- לבחור כל רמת קושי, להתחיל לוח ריק, לבצע מהלך אנושי ראשון ולהשלים משחק עד תוצאה.
- להוכיח באופן דטרמיניסטי את שלוש התוצאות. להשתמש ב־RNG מוזרק בבדיקות דומיין/בקר ובשליטה באקראיות בסביבת בדיקות הדפדפן לפני עליית האפליקציה; אין להוסיף כפתורי debug או פרמטרי URL לגרסה שנמסרת.
- לבדוק נראות, מקלדת ומגע בפריסות portrait/landscape, כולל מסך צר ומסך נמוך. לתעד מגבלות של אמולציה; בדיקות release מלאות במכשירים אמיתיים אינן תנאי חדש בשלב זה.
- לשמור שישה צילומי מסך חובה: Setup, תור אדם, תור מחשב, ניצחון אדם, ניצחון מחשב ותיקו. לצרף גם ראיה להתאוששות משגיאה.
- להכין הוראות הרצה קצרות ודוח מסירה המפרט כל תנאי סיום, תוצאה ומגבלות.

## כיסוי תנאי הסיום

- [x] **בחירת קושי ומשחק שלם:** בדיקת אינטראקציה לכל רמה, לוח ריק, האדם מתחיל, ותוצאה סופית.
- [x] **חוקים:** בדיקות כל שמונת קווי הניצחון לשני הסימנים, תיקו, ניצחון בלוח מלא, ושמירה על חוקיות הלוח.
- [x] **קלט ותורות:** תא תפוס, אינדקס שגוי, הקשות מהירות/חוזרות, תור מחשב ולוח סופי אינם מאפשרים מהלך נוסף. המחשב אינו משחק בתא תפוס או לאחר הסיום.
- [x] **קושי ויכולת לנצח:** RNG נשלט מדגים בחירה אופטימלית וטעות בעלת תוצאה גרועה בכל רמה, fallback כשאין מהלך גרוע, סדר הסתברויות ומסלול ניצחון מול Hard.
- [x] **תזמון וחיי רכיב:** fake timers ובדיקות lifecycle מוכיחים timer יחיד, דחיית callbacks ישנים/כפולים, ניקוי ב־unmount, רקע/חזרה והתאוששות. בדיקות אלו אינן מוסיפות Restart רגיל.
- [x] **ממשק ונגישות:** פתיחה, תורות ותוצאות ניתנים להפעלה במגע ובמקלדת לאורך ולרוחב, עם טקסט קריא, focus ותוויות, ללא overflow או תלות בצבע/צליל.
- [x] **build וראיות:** build production ובדיקות רלוונטיות עוברים; קיימים ששת צילומי החובה, גרסה ניתנת להרצה ודוח מגבלות.

## גבול הסיום

אבן הדרך מוכנה לביקורת רק כאשר כל תנאי הסיום המקוריים מתקיימים והראיות זמינות. תנאי שלא נבדק או שנכשל נשאר פתוח; אין להכריז על השלמה מתוך הצלחת build בלבד.

בסיום המימוש יש להציג למפתח את הגרסה, תוצאות הבדיקות והראיות, ולעצור עד לאישור מפורש בהתאם למסמך אבני הדרך. תוכנית זו אינה כוללת תכנון או מימוש של אבן דרך נוספת.
